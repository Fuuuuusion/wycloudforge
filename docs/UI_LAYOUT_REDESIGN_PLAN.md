# 主界面布局与歌曲行改造计划

更新日期：2026-09-01

状态：用户已确认布局、搜索热搜分栏、来源 Logo 与来源展开交互；可作为后续实施依据

## 1. 计划优先级与执行边界

- 本计划以用户提供的主布局草图、歌曲行补充图、搜索界面标注、来源图标和 2026-09-01 当前仓库 `main`（`d1c5941`）为依据。
- 本计划取代此前讨论中的“推荐歌曲 4 行 × 3 列网格”方案。歌曲继续采用一首占据整行的列表形式。
- 用户已确认搜索来源交互的四项解释：删除顶部“加载更多”并改为自动分页；收起时只显示一个来源、展开时显示三个；第二次点击可用来源立即播放；非搜索页面不临时联网寻找同曲版本。
- `docs/UI_CONTROLS_REDESIGN_PLAN.md` 继续约束收藏、下载、loading、删除、上下首、播放按钮、播放均衡器及歌单卡片的自绘形状和真实状态机；若其尺寸或布局与本文冲突，以本文为准。
- 所有白色横线、竖线只用于草图定位，不进入正式界面；不新增毛玻璃、渐变、阴影、外发光或装饰分隔线。
- 除本文明确规定的来源列状态机、搜索自动分页和发现页布局外，保留现有播放、收藏、下载、删除、歌单、搜索排序、来源服务、右键菜单和批量操作逻辑；不修改 SQLite、在线来源协议和下载文件规则。
- 不触碰或提交仓库中的用户复现数据：`db-backups/`、`ui-repro-data/`、`ui-repro.sqlite*`。

## 2. 当前仓库事实

- `MainWindow` 默认 `1280×800`，最小 `940×600`。
- `TitleBar` 当前高 `48px`，包含 Logo、应用名、`340×30px` 搜索框和三个窗口按钮。
- 主体当前为固定 `200px` 侧栏和右侧 `QStackedWidget`。
- `AccountPanel` 当前位于侧栏底部，头像 `36×36px`，设置按钮也位于该面板内。
- `PlayerBar` 当前为覆盖内容的 `860×80px` 悬浮控件；`MainWindow::positionPlayerBar()` 在窗口变化时手工定位。
- 所有主要歌曲页面复用 `SongListView : QTableView`；当前行高 `64px`，现有列宽依次为 `56 / stretch / 200 / 180 / 70 / 44 / 86`。
- `SongListView` 现有末尾两个操作列分别承担收藏和下载/删除；批量复选框、播放指示器和行号共用首列。
- 推荐页继续使用通用 `SongListView`，推荐歌单最多显示 6 张，卡片代码实际尺寸为 `132×168px`。
- `MainWindow::connectSongListActions()` 通过 `findChildren<SongListView*>()` 为所有列表统一接入下载和批量操作。保留通用列表能避免重新复制该接线。

## 3. 目标布局总览

### 3.1 1920×1080 基准

尺寸均为 Qt 逻辑像素，视觉截图以 Windows 100% 缩放、最大化 `1920×1080` 为主要基准，同时验证 125% 和 150% 缩放。

```text
MainWindow
└─ QHBoxLayout (margin=0, spacing=0)
   ├─ SidebarShell (fixedWidth=240)
   │  ├─ AccountPanel (fixedHeight=224)
   │  ├─ SideBar (stretch=1)
   │  └─ SettingsFooter (fixedHeight=128)
   └─ RightColumn (stretch=1)
      ├─ TitleBar (fixedHeight=48)
      ├─ QStackedWidget (stretch=1)
      └─ PlayerBar (fixedHeight=224)
```

- 左侧导航区贯穿窗口全高。
- 播放器左边界严格等于导航栏右边界，不能进入或覆盖导航栏。
- 播放器右边界贴合窗口右边界，底边贴合窗口底边，不再悬浮，也不保留左右外边距。
- 内容页面只占 `TitleBar` 与 `PlayerBar` 之间的区域，不再通过歌曲列表底部安全区躲避播放器。

### 3.2 最小窗口

- 保留 `940×600` 最小窗口。
- 侧栏仍保持 `240px`；右侧最小可用宽度约 `700px`。
- 高度不足时歌曲列表正常垂直滚动，不压缩到低于计划行高。
- 标题栏搜索框和播放器使用本文定义的紧凑模式，不允许控件重叠或产生水平滚动条。

- 不是隐藏控件，而是从标题栏实现中直接移除；窗口标题属性本身可以继续保留，供任务栏和辅助功能使用。

### 4.2 保留和调整

- 保留搜索图标、输入框、圆角、清空按钮、搜索建议交互和三个窗口按钮。
- 基准搜索框尺寸为 `520×36px`，圆角 `18px`。
- 搜索框在右侧内容区水平居中，不以左侧导航区为中心基准。
- 窗口按钮继续位于最右侧，尺寸和点击逻辑不变。
- 当右侧区域不足 `920px` 时，搜索框宽度按以下公式收缩：

```text
searchWidth = clamp(rightColumnWidth - 190, 280, 520)
```

- 网易云/QQ 音乐按钮仍属于推荐页，保持当前互斥和按需启动逻辑，不移动到全局 `TitleBar`。

## 7. 搜索发现页与自动分页

### 7.1 搜索发现页布局

- 保留搜索历史、热搜词点击搜索、键盘选择和搜索建议逻辑；只重排发现页的视觉容器。
- 搜索历史位于发现页上方，使用全宽区域；没有历史时直接隐藏该区域，不留下空白占位。
- 历史下方使用固定双栏：左侧网易云音乐热搜，右侧 QQ 音乐热搜；两栏 `stretch=1:1`、间距 `24px`，在支持的最小窗口宽度下仍保持左右排列，不改为上下堆叠。
- 发现页内容边距建议为 `left/right=28px`、`top=20px`、`bottom=20px`；标题与首个热词间距 `12px`，热词纵向间距 `6px`。
- 两栏分别保留自己的平台标题、可用状态和热词顺序。网易云失败时 QQ 热搜仍正常显示，QQ 失败时网易云热搜仍正常显示；失败栏显示来源级错误和重试入口，不得清空另一栏。
- 热词只在各自平台列表内部按规范化文本去重，不跨平台合并；同一个词同时出现在两侧是允许的。点击任一热词继续提交其原始搜索文本。
- 删除当前 `QListWidget#searchAssistantList` 的 `#16161E` 灰底、圆角灰色容器和灰色悬停底；发现页背景与页面主背景一致，热词普通态和悬停态都不绘制整块底色，只允许文字颜色、下划线或现有主题强调色变化。
- 搜索建议弹层若继续复用 `QListWidget`，必须使用独立对象名和局部样式，不能因为移除发现页灰底而破坏输入框下拉建议的可读性。

### 7.2 删除红框旧控件

- 从 `SearchPage` 的构造、布局、信号连接和成员中删除 `m_onlineMore`，界面不再出现“加载更多”按钮。
- 删除 `m_variantTree` 及其双击播放路径；同曲的多来源版本全部进入通用歌曲行的来源列，不再在结果列表下方重复显示版本树。
- 删除上述控件后不得留下固定高度、空白间距或不可见占位控件。

### 7.3 滚动自动分页

- 在线结果列表滚动到接近底部时自动请求下一页；建议判定为 `scrollMaximum - scrollValue <= max(pageStep, 160px)`。
- 若首批结果不足以形成滚动条，在当前页完成渲染后继续请求下一页，直到内容超过一个视口、所有来源均已结束或请求失败；每个来源同一时刻最多存在一个分页请求。
- 网易云和 QQ 分别维护 `nextPage/cursor`、`inFlight`、`exhausted` 和错误状态。一个来源结束或失败不能阻止另一个来源继续分页。
- 请求必须携带搜索代次、规范化查询词、来源和页标识；切换关键词、切换页面或销毁 `SearchPage` 后，迟到响应必须被忽略。
- 网络失败时保留已经显示的结果，并在列表底部显示该来源的轻量失败/重试状态；不得自动无限重试，不得恢复旧“加载更多”按钮。
- 新页数据进入现有 `SearchAggregator` 后按既有排序与同曲去重规则合并；相同稳定身份不得重复插入，活动来源切换也不得改变聚合行顺序。
- 自动分页的 loading 只表示真实请求状态；两个来源都没有更多数据时停止监听触发，不进行空请求轮询。

### 7.4 来源图标资源

- 实施阶段把用户提供的三张 `200×200`、32 位 ARGB PNG 复制进仓库资源目录，不在源码或运行时引用桌面绝对路径：
  - `圈圈音乐.png` → `resources/source-icons/qq.png`
  - `网易云音乐.png` → `resources/source-icons/netease.png`
  - `音乐.png` → `resources/source-icons/local.png`
- 生成对应静态灰度资源 `qq-disabled.png`、`netease-disabled.png`、`local-disabled.png`。灰度转换使用固定亮度公式 `Y = 0.299R + 0.587G + 0.114B`，RGB 均写入 `Y`，alpha 通道逐像素保持不变，禁止加白底或改变画布尺寸。
- 将六张图片登记到 `resources/resources.qrc`，统一通过 `:/source-icons/...` 访问；运行时不得反复转换灰度图，也不得依赖桌面目录。
- 歌曲来源列收起时只显示一个 Logo、展开时才同时显示三个；该限制不适用于推荐页右上角两个并列的平台切换按钮。

## 8. 通用歌曲行新布局

### 8.1 作用范围

- 不新增推荐页专用歌曲网格。
- 直接改造通用 `SongListView` 和 `SongRowDelegate`。
- 推荐、收藏、本地歌单、搜索结果、自建歌单详情和在线详情中的歌曲列表统一使用新行样式。
- `SongListModel` 从现有列结构调整为本文八列，在“歌名 - 歌手”和专辑之间增加来源 Logo 列；所有原列号点击、tooltip 和测试必须同步迁移。

### 8.2 行高与封面

- 普通歌曲行由 `64px` 增加到 `112px`。
- 封面由 `36×36px` 增加到 `80×80px`，圆角 `8px`，垂直居中。
- 行与行之间不绘制横线；通过留白形成层次。
- 普通状态不增加整行色块。按下反馈、当前播放提示和现有局部悬停动画继续遵循 `UI_CONTROLS_REDESIGN_PLAN.md`。
- 播放器已改为布局占位后，删除原先用于避开悬浮播放器的 `94px` 列表底部安全区；列表末尾只保留约 `16px` 呼吸空间。
- 顶部 `38px` 批量工具栏继续可见；进入批量模式后显示完整操作按钮。

### 8.3 八列语义与宽度

草图中的歌曲行映射为：

| 列 | 基准宽度 | 显示内容 |
|---|---:|---|
| 0 | `56px` | 批量复选框或当前播放三角/均衡器；普通非播放状态留空，不再显示行号 |
| 1 | `104px` | 独立封面区域，显示 `80×80px` 圆角封面 |
| 2 | `stretch` | 单行“歌名 - 歌手” |
| 3 | `72px` | 来源 Logo；收起状态只显示一个 |
| 4 | `220px` | 专辑名 |
| 5 | `90px` | 时长 |
| 6 | `64px` | 收藏按钮 |
| 7 | `86px` | 下载、loading 或删除下载按钮 |

- 第 2 列文字格式固定为 `歌名 - 歌手`；歌名或歌手缺失时不显示多余连接号。
- 歌名、歌手和专辑均单行右侧省略，完整信息放入 tooltip。
- 失效歌曲在组合标题末尾追加 ` · 失效`，沿用当前弱化颜色。
- 第 3 列来源 Logo 建议显示 `34×34px`，点击区 `48×48px`；缓存、永久下载和失效状态继续通过 tooltip 及必要的封面角标表达。
- 当前播放三角和三柱均衡器放在第 0 列，形状与动画不变。
- 批量模式下第 0 列改画 `16×16px` 复选框；复选框仅在批量模式出现，符合草图“待出现时复选框”的说明。

### 8.4 来源状态与默认优先级

- 三个来源固定为本地、网易云和 QQ 音乐。
- 收起状态只显示一个 Logo，选择顺序为：有效本地文件 → 可用网易云版本 → 可用 QQ 版本。
- 如果没有任何可用版本，则在已经存在的版本中按本地 → 网易云 → QQ 选择一个并显示灰度图。
- 本地可用要求文件真实存在且大小大于 0。
- 在线版本存在有效永久下载或自动缓存文件时，即使来源服务离线也仍然可播放，应显示原色。
- 没有本地音频的在线版本只有在该歌曲 `playable`、来源已启用且服务可用时才显示原色。
- 不可用状态必须区分 tooltip：无此来源版本、来源服务不可用、版权限制、本地文件缺失以及现有详细错误。
- “本地优先”只代表真实本地导入版本；网易云或 QQ 的缓存、永久下载仍保持原平台来源身份。

### 8.5 来源列展开交互

- 第一次点击收起状态的来源 Logo，只打开锚定于来源单元格的竖直浮层，不播放歌曲。
- 浮层不改变歌曲行高，建议宽 `56px`；每个来源按钮点击区 `48×48px`、间距 `8px`、内边距 `8px`。
- 展开状态依次显示本地、网易云、QQ 三个 Logo；这是唯一允许三个 Logo 同时出现的状态。
- 可用或存在有效离线文件的来源显示原色；不可用或不存在的来源显示灰度。
- 第二次点击任意原色 Logo：把该来源设为当前活动版本、关闭浮层并立即播放，且只发出一次播放信号。
- 第二次点击当前原色 Logo：播放当前版本。
- 点击灰度 Logo：不切换、不播放，显示不可用原因。
- 点击浮层外、按 Esc、滚动列表或切换页面：关闭浮层，不播放。
- 浮层根据屏幕空间向上或向下展开；同一时间只能展开一首歌曲。
- 浮层不绘制草图白色边框，只使用接近页面背景的纯色承载。

### 8.6 同曲聚合与稳定身份

- 搜索页继续使用现有 `SearchAggregator::sameRecording()` 和 `SearchResultGroup::variants`，不得重新实现更宽松的去重。
- 一个聚合组始终只显示一行；切换来源不能新增第二行，也不能改变搜索排序。
- 聚合行稳定身份使用 `SearchResultGroup::identity`，不能随活动来源的 `Song::selectionIdentity()` 改变。
- 切换来源只替换该行实际用于播放、收藏、下载和添加歌单的活动 `Song`；数据库中的 `(source, remote_id)` 记录继续分开保存。
- 批量选择、异步封面刷新和排序后必须保留聚合行选择。
- 搜索以外页面仍使用同样的来源列和浮层，但只有当前页面已知的单一来源可用；其他来源显示灰度“无此来源版本”，不得临时联网执行同曲搜索。

### 8.7 点击和状态规则

- 点击封面、组合标题、专辑或时长：播放当前活动来源，且只触发一次。
- 点击第 0 列复选框：只切换批量选择。
- 点击第 3 列来源：严格执行“第一次展开、第二次选择并播放”的来源状态机，不串到整行播放。
- 点击收藏：只收藏或取消收藏，不触发播放。
- 点击下载/loading/删除下载：只执行对应真实状态操作，不触发播放。
- 双击不能在单击基础上重复触发播放。
- 右键菜单、添加歌单、从歌单移除和按来源删除保持当前内容及业务语义。
- 普通单来源行继续使用 `Song::selectionIdentity()`；搜索聚合行必须改用 `SearchResultGroup::identity`，确保来源切换不丢失批量选择。
- 下载 loading 必须继续绑定 `DownloadService`，不得用计时器伪造完成。

### 8.8 窄宽度规则

右侧内容区宽度不足时按顺序让步：

1. 专辑列从 `220px` 收缩到 `140px`。
2. 封面列从 `104px` 收缩到 `88px`，封面从 `80px` 降到 `68px`。
3. 时长列从 `90px` 收缩到 `70px`。
4. 极窄状态隐藏专辑列，但专辑内容仍保留在组合标题 tooltip 中。

来源、收藏和下载列不得隐藏；行高保持 `112px`，不因窗口变窄恢复成细行。

## 9. 底部播放器

### 9.1 外部几何和背景

- 移除 `PlayerBar::setFixedSize(860, 80)` 和 `MainWindow::positionPlayerBar()` 的悬浮定位路径。
- `PlayerBar` 改为 `QSizePolicy::Expanding / Fixed`，固定高 `224px`。
- 播放器位于 `RightColumn` 最底部，左侧不越过导航栏右边界，横向铺满至窗口右边界。
- 外层使用矩形背景，不保留会露出底层颜色的外侧圆角和边距。
- 主背景当前为 `#0E0E14`，播放器背景从当前 `#1B1B24` 改为建议值 `#14141B`。该颜色只比主背景略亮，减少区域割裂感。
- 不绘制顶部边线；播放器与页面只通过轻微颜色差区分。

### 9.2 内部四区

在 `1920×1080`、右侧可用宽约 `1680px` 时使用以下比例：

| 区域 | 比例 | 主要内容 |
|---|---:|---|
| 当前歌曲信息 | `28%` | 大封面、歌名、创作者、来源/歌曲状态 |
| 收藏与下载 | `13%` | 收藏和下载按钮纵向排列 |
| 进度与播放控制 | `28%` | 时间、进度条、上一首、播放/暂停、下一首 |
| 音量与工具 | `31%` | 静音、音量、循环模式、歌词、播放队列 |

- 当前歌曲封面基准 `148×148px`，保持当前封面裁切方式。
- 歌名、创作者和来源/歌曲状态位于封面右侧，均允许右侧省略。
- 收藏和下载控件保持原自绘图形、状态机和点击区，改为上下排列。
- 中间区上方为当前时间、进度条、总时长，下方为上一首、播放/暂停、下一首。
- 右侧上方为静音和音量条，下方为循环模式、歌词和播放队列。

### 9.3 播放器响应式规则

- 右侧宽度 `>= 1100px`：完整四区。
- `780–1099px`：封面降为 `112×112px`，缩小区间距，音量条缩短；四个区域仍存在。
- `< 780px`：进入紧凑模式，隐藏封面、歌词和队列，隐藏独立音量条但保留静音按钮；歌名、收藏、下载、进度、上一首、播放/暂停、下一首和循环模式必须保留。
- 任何宽度下，上下首和播放按钮的完整点击区域都不能被压缩或裁切。
