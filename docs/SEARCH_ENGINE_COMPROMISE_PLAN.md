# 搜索引擎优化折中实施方案

## 文档状态

- 版本：1.3
- 状态：用户已审核；阶段 1～6 已完成
- 审核记录：用户已明确要求“开工”并持续要求按本文严格执行
- 完整方案基线：docs/SEARCH_ENGINE_FULL_PLAN.md

本文记录“不建设独立本地全文搜索引擎，保留轻量本地搜索，在线搜索直接请求网易云和 QQ 音乐”的折中方案。本文一旦经用户确认，将作为本轮搜索功能实施、测试和验收的严格基线；未经再次确认，不扩大或缩减范围。

## 方案结论

第一版不建设 FTS5 搜索索引，也不引入 RapidFuzz、拼音词库或本地歌词全文索引。

搜索由三部分组成：

1. 本地曲库轻量搜索立即返回。
2. 网易云和 QQ 音乐在线搜索并发请求、分别增量返回。
3. 聚合层统一结果结构，执行相关度分层、来源内热度标准化、同曲聚合和稳定排序。

该方案优先完成普通用户最常用的在线搜索体验：

- 可以单独搜索网易云或 QQ 音乐。
- 可以把两个来源合并搜索。
- 相关结果中热门歌曲优先。
- 支持热搜、输入联想、历史、分类、分页和来源级错误。
- 一个来源失败时，另一个来源和本地搜索仍然工作。
- 小型和中型本地曲库可以按歌名、歌手和专辑搜索。

该方案不承诺完整方案中的本地拼音、首字母、歌词全文、复杂错字纠正和高级查询能力。

## 用户可见功能范围

### 搜索范围

搜索页提供四个范围：

- 综合
- 本地
- 网易云
- QQ 音乐

“综合”模式同时执行本地、网易云和 QQ 搜索。各来源独立加载、独立分页、独立失败，不等待所有来源完成后才显示。

### 搜索分类

第一版正式支持：

- 综合
- 单曲
- 歌手
- 专辑
- 歌单

在线歌词搜索作为来源能力项处理：

- 平台接口能够稳定提供时，在“歌词”分类中显示该来源结果。
- 某个来源不支持或返回结构不稳定时，只禁用该来源的歌词搜索。
- 不因为在线歌词接口不稳定而阻塞单曲、歌手、专辑和歌单功能。
- 不实现本地歌词全文搜索和歌词时间点检索。

### 搜索框交互

- 输入为空并获得焦点时显示搜索历史、平台热搜和默认搜索词。
- 本地联想立即显示，网易云和 QQ 联想异步补充。
- 在线联想至少输入 2 个字符后请求。
- 输入请求使用 250～300ms 防抖。
- 上下键选择候选，Enter 打开或执行搜索，Ctrl+K 聚焦搜索框。
- 返回搜索页时恢复关键词、范围、分类、滚动位置及来源分页状态。
- 快速连续输入时，旧关键词的迟到响应不得覆盖新关键词。

### 结果展示

综合页按对象类型分区展示，避免把不同对象混为一列：

- 最佳匹配
- 歌手
- 单曲
- 专辑
- 歌单
- 在线歌词（仅在来源支持时出现）

每条结果显示来源标签。聚合同一首录音后，结果行可以展开查看网易云和 QQ 的版本、可播放状态及版权限制。

## 搜索执行流程

每次查询按以下顺序执行：

1. 对关键词做去首尾空格、大小写统一和基础 Unicode 规范化。
2. 创建新的查询 generation，并取消或逻辑废弃上一代在线请求。
3. 从内存中的本地歌曲快照执行轻量匹配，在后台工作线程计算并立即返回。
4. 检查在线搜索缓存；命中时先显示旧结果并标记后台刷新。
5. 防抖结束后，并发请求网易云和 QQ 音乐。
6. 任一来源返回后立即更新该来源分区，不等待另一个来源。
7. 聚合层统一执行相关度、热度、同曲识别和稳定排序。
8. 后返回的同代请求补充结果；非当前 generation 的结果直接丢弃。
9. 单个来源超时、离线或结构异常时，仅显示该来源错误和重试入口。

UI 线程不得执行同步网络请求、逐首数据库查询、大量封面解码或完整列表重建。

## 本地轻量搜索

### 数据来源

本地搜索基于 LibraryService 已加载的歌曲快照，不为每次按键重新查询 SQLite。歌曲新增、删除、下载、缓存或元数据变化后增量刷新快照。

### 匹配字段

第一版只匹配：

- 歌名
- 歌手
- 专辑

支持：

- 完全一致
- 前缀一致
- 包含关键词
- 歌手与歌名组合命中

不支持：

- 本地拼音全拼
- 本地拼音首字母
- 本地歌词全文
- 本地错字自动纠正
- NEAR、布尔表达式等高级查询

本地扫描必须在后台线程运行，并限制返回候选数量。即使曲库较大，也不得阻塞界面；若未来真实曲库规模使扫描不能达到性能目标，再按完整方案升级 FTS5，而不是在 UI 线程增加复杂匹配。

### 离线边界

断网时仍可按歌名、歌手和专辑搜索：

- 本地导入歌曲
- 已缓存歌曲
- 永久下载歌曲
- 已保留在曲库中的其他歌曲记录

平台已下架但本地仍有文件的歌曲，只要本地元数据匹配，仍然可以找到。无法通过拼音、歌词或错字找到。

## 在线来源接口

### 统一契约

UI 不解析网易云或 QQ 原始 JSON。每个来源转换为统一对象：

- 查询分类
- 标题、歌手、专辑和封面
- 来源 ID 与字符串远端 ID
- 平台返回名次
- 平台热度信号
- 可播放、VIP、DRM、地区和版权状态
- 来源独立分页状态
- 来源独立错误

所有歌曲操作继续使用稳定身份 (source, remote_id)，不得使用结果行号作为歌曲身份。

### 网易云

接入并验证：

- 热搜
- 默认搜索词
- 输入联想
- 单曲搜索
- 歌手搜索
- 专辑搜索
- 歌单搜索
- 在线歌词搜索（接口稳定时）

### QQ 音乐

由本机 QQ 包装服务提供稳定的 ok、data、error 契约，接入并验证：

- 热搜
- Smartbox 或等价联想
- 单曲搜索
- 歌手搜索
- 专辑搜索
- 歌单搜索
- 在线歌词搜索（接口稳定时）

QQ 服务按需启动。冷启动只延迟 QQ 结果，不重复请求网易云，也不阻塞本地结果。

### 故障隔离

- 网易云失败不影响 QQ 和本地。
- QQ 服务未启动、端口占用、签名错误或接口字段变化时，只禁用 QQ 搜索。
- 临时网络错误保留已显示缓存，不清空结果。
- 每个来源提供单独重试入口。
- 所有在线请求使用代次校验和对象生命周期保护。

## 在线缓存与主数据库

缓存只用于提高响应速度，不是本地搜索引擎：

- 热搜缓存约 5 分钟。
- 输入联想缓存约 10 分钟。
- 在线结果缓存约 15～30 分钟。
- 缓存键包含来源、规范化关键词、分类、页码和筛选。
- 缓存允许先显示后刷新。
- 缓存损坏可以直接清理，不得影响主数据库。

浏览搜索结果时不把所有返回歌曲写入 library.db。只有播放、收藏、加入歌单、缓存或下载时，才按稳定来源身份安全 upsert，避免“只浏览过的在线歌曲”污染本地歌单。

## 默认排序

### 排序目标

默认行为不是简单交错两个平台的返回顺序，也不是让热门但不相关的歌曲占据顶部。

排序键固定为：

1. 相关度层级。
2. 同层级内标准化热度降序。
3. 跨平台共识。
4. 收藏、最近播放等弱个人信号。
5. 稳定歌曲身份，保证重复搜索顺序稳定。

### 相关度层级

从高到低：

1. 歌名完全一致。
2. 歌名前缀一致。
3. 歌名包含关键词。
4. 歌手与歌名组合命中。
5. 歌手完全一致或前缀一致。
6. 专辑名称命中。
7. 平台返回的其他相关结果。

热度不能让低相关结果跨越更高相关层级。例如搜索“晴天”时，歌名完全一致的“晴天”必须排在仅因热门而被平台召回的弱相关歌曲之前。

### 热度标准化

网易云和 QQ 的原始热度数值不能直接比较。每个来源内部按以下优先级建立相对热度：

1. 平台明确返回的播放、流行度或热度字段。
2. 平台搜索结果名次。
3. 歌手热门歌曲接口名次。

热度转换为来源内百分位后再参与跨来源排序。两个平台都排名靠前的同一录音可以获得很小的共识加成。

该值代表“基于平台可见数据估算的相对全网热度”，不宣称是绝对、精确的全网播放量。

### 可选排序模式

- 综合
- 热度
- 最近播放
- 本地优先

“热度”模式仍保留最低相关度门槛，避免无关热门内容进入顶部。

## 跨来源同曲聚合

同曲聚合在结果层实现，不依赖 FTS5。

判断条件包括：

- 规范化歌名
- 主要歌手
- 版本标记
- 时长容差，默认约 2～3 秒

以下内容不能误合并：

- Live
- Remix
- 翻唱
- 伴奏
- 不同语言版本
- 明显不同录音

聚合后保留所有来源身份，不删除来源结果。默认播放版本按永久下载、自动缓存、本地文件、在线可播放状态和用户来源偏好选择。某个来源存在 VIP、DRM、403、地区或版权限制时，可以尝试同组其他合法可播放来源，但不得绕过限制。

## 响应时间目标

正常设备和网络条件下的目标：

- 输入后 100ms 内显示本地结果或已有缓存。
- 在线请求在 250～300ms 防抖后发出。
- 常见情况下约 300ms～1s 出现第一个在线来源。
- 两个已启动来源通常在约 1.5s 内完成首屏。
- QQ 服务冷启动时允许 QQ 结果延迟到约 1～3s。
- 一个来源超过超时阈值时，不延迟另一个来源和本地结果。
- 搜索、排序和合并不得造成肉眼可见的 UI 卡顿。

这些数值是性能目标，不是第三方平台接口的硬性保证。网络慢时必须保持增量结果、来源级加载状态和可取消性。

## 实施阶段

### 阶段 1：搜索编排和基线（已完成）

- 盘点当前网易云、QQ 和本地搜索实现。
- 固化统一查询 DTO、结果 DTO、来源能力和稳定身份。
- 增加查询 generation、取消、超时和来源级状态。
- 保证本地结果先返回，两个在线来源并发增量返回。

### 阶段 2：平台搜索能力（已完成）

- 完成网易云热搜、默认词、联想及分类搜索。
- 完成 QQ 热搜、联想及分类搜索包装契约。
- 为第三方响应增加固定夹具和未知字段兼容。
- 验证在线歌词接口，按来源能力启用或禁用。

### 阶段 3：本地轻量搜索（已完成）

- 建立线程安全的本地歌曲快照。
- 实现歌名、歌手、专辑的完全、前缀和包含匹配。
- 后台执行、候选上限和结果高亮。
- 验证本地导入、缓存、下载和下架歌曲的可检索性。

### 阶段 4：排序与同曲聚合（已完成）

- 实现固定相关度层级。
- 实现来源内热度百分位和跨平台共识。
- 实现同曲识别、版本展开和可播放来源选择。
- 保证收藏、批量操作、下载和播放使用稳定歌曲身份。

### 阶段 5：搜索界面与缓存（已完成）

- 完成范围、分类、历史、热搜、联想和键盘操作。

- 完成在线结果缓存、先显示后刷新和页面状态恢复。
- 确保单张封面完成不触发全局列表重建。

### 阶段 6：稳定性与验收（已完成）

- 执行快速输入、迟到回调、来源离线、QQ 冷启动和缓存损坏测试。
- 执行热度排序、同曲误合并和稳定身份测试。
- 运行现有全部自动化测试及新增搜索测试。
- 重新构建并启动正式应用进行人工验收。

## 测试与验收标准

### 核心搜索

- “综合”搜索能同时显示本地、网易云和 QQ 结果。
- 切换到单一来源后，只请求和显示对应来源。
- 单曲、歌手、专辑和歌单分类均可独立搜索和分页。
- 来源返回顺序不同，不会导致最终结果随机抖动。

### 排序

- 搜索准确歌名时，精确匹配先于弱相关热门歌曲。
- 同相关度层级内，平台可见数据更热门的歌曲优先。
- 网易云和 QQ 原始数值不直接比较。
- 缺少明确热度字段时，使用平台名次作为可解释的代理信号。

### 稳定性

- 快速连续输入时，旧结果不会覆盖新结果。
- 网易云离线时，QQ 和本地仍可搜索。
- QQ 服务失败时，网易云和本地仍可搜索。
- 关闭页面、切换分类或退出应用后，迟到回调不访问已销毁对象。
- 搜索过程没有同步网络等待和明显 UI 卡顿。

### 本地边界

- 断网时可以按歌名、歌手或专辑找到本地导入、缓存和下载歌曲。
- 平台下架但本地仍有文件的歌曲可以按元数据找到。
- 不能通过本地歌词、拼音首字母或错字找到歌曲，界面不得暗示已经支持。
- 只浏览但未播放、缓存或下载的在线歌曲不会因此进入本地歌单。

### 多源歌曲操作

- 同曲聚合不误合并 Live、Remix、翻唱、伴奏和不同录音。
- 聚合结果的播放、收藏、添加歌单、批量操作和下载均使用稳定来源身份。
- 某一来源不可播放时，只显示该来源限制，并可选择同组其他合法来源。

## 编译、测试和提交纪律

- 每个实施阶段完成后单独 commit 并 push 到 origin/main。
- 不把无关工作区修改混入搜索提交。
- 每次编译或测试失败都记录到 docs/HANDOFF.md，包含错误现象、根因和已验证的可行方案。
- 如果失败属于缺失环境、工具链或账号配置，先向用户确认是否配置。
- 阶段验收失败时先修复当前阶段，不带着已知问题进入下一阶段。
- 最终必须运行现有全部自动化测试、新增搜索测试、正式构建和应用启动检查。

## 明确不在本轮实施的内容

- 独立 FTS5 搜索数据库。
- RapidFuzz 本地模糊匹配。
- 本地拼音全拼和首字母词库。
- 本地歌词全文索引及命中时间跳转。
- 高级布尔、短语和邻近查询语法。
- 精确、可审计的绝对全网播放量排名。
- 平台版权、VIP、DRM、403 或地区限制绕过。
- QQ 或网易云云端写操作。

## 后续升级兼容

统一查询 DTO、结果 DTO、相关度层级、来源路由、稳定歌曲身份和聚合层必须与完整方案兼容。未来增加 FTS5 时，只替换或扩展本地候选召回层，不重写在线来源、结果界面、热度排序和同曲聚合。

## 审核确认点
