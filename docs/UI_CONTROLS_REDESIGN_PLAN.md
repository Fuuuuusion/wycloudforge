## 7. 下载、Loading 与删除组合控件

下载参考：[faxriddin20 / slimy-yak-12](https://uiverse.io/faxriddin20/slimy-yak-12)
删除参考：[vinodjangid07 / smart-emu-83](https://uiverse.io/vinodjangid07/smart-emu-83)
状态过渡参考：[MohammadSahragard / Animated Download Button](https://github.com/MohammadSahragard/Animated-Download-Button)

### 7.1 状态机

1. **可下载**：显示淡灰色下载箭头和托盘。
2. **点击下载**：箭头在约 `200ms` 内向下落入托盘，同时立即发出现有下载请求，不等待动画结束。
3. **下载中**：箭头与托盘收拢为约 `16×16` 的 loading 图标。图标采用约 270° 的细圆弧，以约 `700–800ms` 一周持续旋转；仅刷新自身区域。
4. **下载完成**：loading 图标停止，圆弧收拢并在约 `200ms` 内变形为垃圾桶，随后进入已下载/可删除状态。
5. **下载失败或取消**：loading 立即停止，在约 `160–200ms` 内反向变回下载图标；不得显示虚假的完成状态。
6. **点击删除**：使用 `smart-emu-83` 的垃圾桶下沉和文字展开效果；删除成功后，歌曲若仍留在列表则反向变回下载状态，若当前筛选会移除该歌曲则遵循现有列表刷新结果。

### 7.2 真实状态要求

- loading 必须绑定现有 `DownloadService` 任务状态和 `tasksChanged` 等真实结果，按稳定歌曲身份关联，禁止用固定延时假装下载完成。
- 歌曲体量较小时 loading 可只停留很短时间，不设置人为最短展示时长；若下载在入场动画结束前完成，完成当前短动画后立即转为删除。
- 下载业务、网络请求、缓存和文件落盘逻辑保持不变，只增加 UI 状态映射。
- 下载中不得重复触发下载；失败或取消后恢复可点击。

### 7.3 作用范围

- 歌曲行操作列使用完整的“下载 → loading → 删除”状态控件。
- PlayerBar 下载按钮同步使用相同状态语言：未下载时为下载，下载中为 loading，已下载时变为删除。
- PlayerBar 的删除状态只能删除当前歌曲的已下载本地副本，必须复用现有下载删除路径，不得删除歌单成员、音乐库记录或在线歌曲身份。
- 允许为 PlayerBar 增加明确的删除下载 signal，并在 `MainWindow` 中做最小接线；工具提示必须随状态变为“下载”“下载中”“删除下载”。

## 9. 歌曲行按钮与播放动效

参考：[Praashoo7 / thin-sloth-31](https://uiverse.io/Praashoo7/thin-sloth-31)

### 9.1 结构与悬停

- 不实现示例顶部 Spotify Logo 和 “Currently Playing”。
- 保持现有 `64px` 行高、`36px` 封面和所有列宽。
- 行悬停由参考原版 `400ms` 改为 `200ms`；整行圆角背景平滑淡入，不再瞬间向上移动表格内容。
- 按下时背景略深，内容最多下沉 `1px`，不得改变表格行几何或造成列表抖动。
- 当前歌曲使用弱红色行背景和红色标题；失效歌曲继续保留弱化文字及“失效”标识。

### 9.2 单击播放

- 单击封面、歌名、歌手、专辑或时长区域即可触发 `playRequested`。
- 单击批量复选框、收藏、下载、loading、删除等独立操作区时，只执行该操作，不触发播放。
- 右键菜单不触发播放；双击不得重复发出额外播放请求。
- `playRequested` 的参数和歌曲身份映射保持不变；其触发条件从双击调整为上述单击行为是本计划已批准的交互变更。

### 9.3 播放动效与动态均衡器

- 非当前歌曲显示静态播放三角；单击时三角短暂收缩。
- 只有真实当前歌曲进入 Playing 状态后，三角才在约 `200ms` 内变为三柱均衡器。
- 均衡器保留参考页的三根细柱和错峰效果：单轮约 `1s`，各柱相位错开约 `200ms`。
- 实现建议限制为约 `30fps`，只刷新约 `14×24px` 的均衡器区域。
- 暂停、停止、窗口最小化或不可见时停止循环刷新；恢复播放后继续。
- 允许把现有 `PlayerService::playingChanged(bool)` 通过 `MainWindow` 最小接线传给全部 `SongListView`，确保动画跟随真实状态而不是当前歌曲 ID。

## 12. 性能与可访问性要求

- 普通 `200ms` 微动效不延迟 signal，只改变局部绘制属性。
- loading 只在真实下载任务存在时运行；动态均衡器只在真实播放且窗口可见时运行。
- loading 与均衡器分别限制为小区域、单实例或少量并发实例，避免全列表持续重绘。
- 所有按钮保留鼠标指针、工具提示、键盘焦点和 accessible name；焦点反馈不得在鼠标点击或对话框关闭后残留。
- 下载、删除、播放等高风险交互必须保留明确工具提示和禁用状态。
